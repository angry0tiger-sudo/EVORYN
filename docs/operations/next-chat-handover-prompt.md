## 2. Evidence: both model families are rejected

Latest recorded regime snapshot: 11,439 hourly BTC-USDT Spot candles, 23 public-history pages, zero detected gaps, from 2025-07-01 13:30 UTC to 2026-10-21 03:30 UTC.

- HMM: 5/5 folds, balanced accuracy 89.76%, macro-F1 82.42%, regime-gated SMA mean net return -1.9954% per test fold; 111 closed trades.
- XGBoost: 5/5 folds, balanced accuracy 99.73%, macro-F1 99.79%, regime-gated SMA mean net return -2.3676% per test fold; 122 closed trades.
- Unfiltered SMA averaged -0.1999%; Buy-and-Hold averaged +0.9950% under the same simulated cost assumptions.
- Both models failed the economic acceptance gate; no Champion qualifies.

**Near-99% score trap:** the regime target is generated by thresholding trailing 24-bar return, and that same return is an input feature. The high XGBoost score mainly reproduces its label rule. Call this target/feature or definitional leakage. Do not automatically claim classic future-row look-ahead leakage unless a separate causal audit demonstrates it.

The prior Meta-Label candidates remain rejected too: XGBoost and LightGBM evaluated only 11/13 expected folds. Two folds were non-evaluable after purging, every evaluated threshold abstained, both models closed zero trades, and acceptance failed. Do not weaken gates to manufacture a pass.

Data limitations are unresolved: UDF volume units are unknown, historical order-book depth is absent, spread/slippage are assumptions, and provider data-use terms are unreviewed.

## 3. Main task: build an end-to-end Intelligence Core, offline first

The owner explicitly wants a more advanced system, not abandonment after failed models. Build an auditable, reproducible, cost-adjusted research and Paper Intelligence Core. Do not promise guaranteed persistent profit.

### Phase 31 — Triple-Barrier labels
1. Define a timestamped causal base event, initially a documented existing SMA event.
2. At event time, freeze volatility scale, upper profit barrier, lower stop barrier and vertical time limit from completed bars only.
3. Record barrier touched, event interval, holding time, gross return and net return after the cost model. Handle ambiguous OHLC first-touch order conservatively.
4. Purge training events whose label intervals overlap validation/test and add a documented embargo. Fit thresholds/parameters on train windows only.
5. A label may depend on the price path after its event by design; the feature row may not. Add feature-prefix and event-boundary leakage tests.

### Phase 32 — Cross-fitted Meta-Labeling
1. A base strategy proposes side/exposure using information available at event time.
2. Create chronological out-of-fold base signals. Train the meta learner only on out-of-fold proposals and event-time features, never in-sample base predictions.
3. Use Triple-Barrier net outcome labels; calibrate probability on separate validation time, never test.
4. Preserve abstention. Compare majority/constant baseline, unfiltered base strategy and Buy-and-Hold on identical windows.
5. Report PR-AUC, precision at declared coverage, class prevalence, calibration/Brier/log loss, abstention, trades, net return, turnover, drawdown and paired-fold bounds.

### Phase 33 — Calibrated dynamic sizing
1. Start from an independently approved small equity-risk budget and loss per unit implied by a frozen stop distance. Use calibrated confidence and volatility only as bounded multipliers.
2. Missing stop distance/conversion, bad calibration, stale/gapped data, unknown state or risk HALT means zero new exposure.
3. Deterministic Risk Engine is final authority. Model confidence cannot override max loss, exposure, concentration, notional, freshness, unresolved orders or HALT.
4. Compare fixed-risk, volatility-only and confidence-plus-volatility sizing on identical test windows and costs. Avoid unconstrained Kelly sizing.

### Phase 34 — Reinforcement Learning, last
1. Defer RL until earlier baselines and the simulator are credible.
2. Simulator must model information and fill timing, fees, spread/slippage, partial/no fills, stops/expiry, stale/gapped data, accounting, halts and recovery.
3. Use offline bounded discrete actions such as flat, enter-small, hold, reduce and exit. Agent cannot adjust safety limits, clear HALT or call a Live exchange client.
4. Reward must be net-of-cost with drawdown/tail-risk and turnover penalties. Test multiple seeds/scenarios, untouched chronology and multiple-search bias; compare deterministic baselines.
5. Never train online against Live. Simulator reward is not proof of trading profit.
